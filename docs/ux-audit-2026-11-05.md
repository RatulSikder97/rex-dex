# REX UI/UX audit — production readiness (2026-11-05)

Scope: every screen in Mission and Code layouts, both built-in themes (dark, light), at 1440×900, 1280×800 and the 1024×680
desktop minimum. Screenshots were taken in an isolated Playwright context (`.playwright-mcp/pro-shoot.js`, which installs
`browser.__shoot(page, cfg)`). Before shots: `.playwright-mcp/pro-before-{dark,light}-*.png`, `pro-before-1024-dark-*.png`,
`pro-before-empty-dark-*.png` (empty project list, mocked). After shots: `.playwright-mcp/pro-after-final-{dark,light}-*.png` (1280×800), `pro-after-final-1024-dark-*.png`, and per-area sets `pro-after-{mission,hubops,hub2,studio,code}-*.png`, plus `pro-after-firstrun-dark-1280.png`, `pro-after-appcrash-dark.png`, `pro-after-notfound-dark.png` and `pro-after-rail-{1024,940}-dark.png`.

Owner brief: "not looking pro". It should feel like a native desktop app (VS Code / JetBrains / Linear), with calm polish and easy
navigation: dense 22–28px rows, square full-bleed selection, quiet section headers, the arrow cursor on chrome, no glowing web CTAs and
no rounded web accordions.

Priority: **P0** looks broken or unprofessional, or blocks a new customer · **P1** inconsistent · **P2** polish.

## Design system (the reference for every fix)

| Axis | Rule |
|---|---|
| Type | 11 meta · 12 controls/secondary · 13 body/rows · 15 section title · 20 page title |
| Spacing | 4-px grid (4 · 8 · 12 · 16 · 24 · 32) |
| Radius | 4 controls/rows/badges · 6 cards/panels · 8 dialogs/popovers/composer. No pill/rounded-xl on chrome. |
| Buttons | `btn` (secondary 28px) · `btn-primary` · `btn-ghost` · `btn-danger` · `btn-danger-ghost` · `btn-sm` 24px · `icon-btn` 24 / `icon-btn-lg` 28. One primary per view, top-right of the header. |
| Inputs | `input` 28 / `input-sm` 24, `label`, `help`, native checkbox (accent-colored), `Switch`, `seg` segmented, `tabs` underline tabs |
| Status | `pill` (+ `-accent/-ok/-warn/-err`), `count` |
| Surfaces | flat, 1px `line` borders; shadow only on floating layers (`popover`, dialogs, toasts) |
| Layout | `Page` / `PageHeader` (title, description, actions top-right); Mission pages sit under a 36px frame (Back · breadcrumb · Open in Code mode · Close) |
| States | `LoadingRows`/`Skeleton` (fixed heights), `EmptyState`, `ErrorState` (Retry), `ViewErrorBoundary`, `CrashScreen` |
| Color | theme tokens only (bg, editor, side, panel, elev, hover, active, input, line, fg, muted, faint, accent, ok, warn, err) + color-mix |

Source: `src/app/globals.css` (`@layer components`) and `src/components/ui/kit.tsx`.

## Remaining recommendations for launch

- **Backend copy** (`src/lib/connections.ts`, marketplace manifests): connection names such as "GitHub (MCP)" and "Browser Automation (Playwright MCP)", and `setupHint` text that says "Click Connect with Google", should drop "MCP" and say "Sign in with Google" to match the new buttons.
- **Ops error codes** (`src/lib/ops/{containers,exec,overview}.ts`): return a structured `code` (e.g. `podman_not_running`, `ssh_publickey`) next to raw stderr, so the UI can stop regex-mapping in `ops/shared.tsx` `friendlyError()`.
- **Extension READMEs**: add a `readme` manifest field, or have `/api/plugins/:id` read README.md, so the Details tab can show real docs.
- **`/api/threads/all`**: don't return threads that belong to no project when a projectId is given (or none is set).
- **Search → line**: add an optional `line` to the `file` TabSpec, so search results open at the match.
- **Menu bar**: one leftover is unconfirmed. The scripted `toasts` shot still shows "File" highlighted, probably because the scripted pointer is parked on it. Check by hand.
- **Crash reporting (opt-in)**: wire `crashReport()` (`ui/ErrorBoundary.tsx`) to an opt-in uploader (Sentry or similar) behind a Settings ▸ Privacy toggle; today Save report writes a local .txt file.
- **Product analytics (opt-in)**: first-run completion, agent install success, first task sent and first deliverable are the funnel to instrument, with a clear opt-in on the setup screen.
- **Licensing**: license key / trial state in Settings ▸ Account and a non-blocking trial banner in the status bar; the Electron shell should validate offline with periodic online refresh.
- **Auto-update**: electron-updater with a status-bar "Restart to update" item (the neutral status bar has room for it), plus release notes in Help.
- **Docs site + in-app help**: Help ▸ Documentation, a support link for Save report, and keyboard-shortcut docs (the in-app sheet exists).
- **Visual regression**: `.playwright-mcp/pro-shoot.js` already drives every screen; turn it into a CI job that diffs against approved baselines (dark/light × 1280/1024).
- **Component tests**: there's no test harness. Add Vitest + Testing Library for `ui/kit.tsx`, `Onboarding`, `ErrorBoundary`, and the Mission page/back/Esc behaviour.
- **Disk**: the dev machine is at ~1 GB free (`.next` is 2.3 GB). Clear `.next/cache` and old screenshots before the next build.
- Remove the dev-only `window.__rex` hook if you don't want it in dev builds (it's stripped from production already).
